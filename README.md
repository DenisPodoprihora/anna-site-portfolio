# Anna Zhdankina — portfolio

Одностраничный сайт-портфолио UX/UI & product designer.

## Стек

Чистый HTML / CSS / JS — без сборки, npm и зависимостей.

## Структура

```
index.html              разметка
assets/css/style.css    стили
assets/js/main.js       подстановка текстов EN/RU
assets/fonts/           DM Sans (variable, woff2)
assets/icons/           svg-иконки и фавикон
assets/img/             фотографии проектов и портрет
content/content.json    все тексты сайта парами en/ru
```

## Тексты и языки

Все тексты вынесены в `content/content.json` в виде пар `{ "en": "...", "ru": "..." }`
и подставляются по ключу из `data-i18n`. Разметка хранит английский текст как
fallback, поэтому сайт остаётся рабочим, если JSON не загрузился.

По умолчанию всегда английский: русская версия ещё не вычитана, и на неё нельзя
попасть случайно. Язык браузера не учитывается, посмотреть русскую можно только
явно — `index.html?lang=ru`. Переключатель языка и запоминание выбора появятся
позже; тогда же вернётся и определение языка браузера.

## Ссылки

- **CV** лежит на Google Drive, и на него ведут два разных адреса одного файла:
  кнопка «Download CV» в шапке качает файл сразу (`uc?export=download&id=...`),
  чип «CV» в контактах открывает просмотр в новой вкладке (`file/d/.../view`).
  Править в двух местах `index.html`; при замене файла менять надо обе.
- **Карточка проекта**: картинка и кнопка «View project» ведут в одно место и
  открываются в новой вкладке, поэтому URL продублирован в `.project__cta` и в
  `a.project__media`. Исключение — карточка 03 «Coming soon»: кнопки нет,
  картинка осталась `<div>` без ссылки и без ховера.
- **Explorations**: шесть карточек ведут на шоты в Dribbble. Порядок ссылок в
  разметке не совпадает с порядком карточек — они расставлены по содержимому
  картинок, так что при замене картинки надо проверить и ссылку.

## Масштабирование

Макет нарисован на 1440px и на этой ширине воспроизводится один в один. На любой
другой ширине страница **не перестраивается, а масштабируется целиком**: `zoom`
в `body` умножает разом кегли, отступы, картинки и размеры компонентов, поэтому
сетка и позиции остаются макетными — только меньше или больше.

- Коэффициент `viewport / 1440` считает скрипт в `<head>` и кладёт в `--fit` —
  именно в `<head>`, чтобы значение успело примениться до первой отрисовки.
- **Верхнего предела нет намеренно.** На 1920 это 1.33, на 2560 — 1.78, на
  3440 — 2.39. Чтобы ограничить рост, достаточно вернуть `Math.min` в скрипте.
- `documentElement.clientWidth`, а не `innerWidth`: последний включает ширину
  полосы прокрутки.
- `body` имеет жёсткую `width: 1440px`, потому что `zoom` не сужает элемент с
  `width: 100%`. По той же причине `margin: 0 auto`.
- Ниже 768px масштабирование выключается (`--fit` = 1), иначе `zoom` наложился
  бы поверх мобильной вёрстки и уменьшил её второй раз.

## Мобильная раскладка

До 768px (фрейм 166:20210, 375×4322) страница перестраивается в одну колонку со
своими кеглями и отступами. Всё, что описывает десктопный макет 1440px, остаётся
в силе от 768px и выше; вся мобильная часть лежит в одном
`@media (max-width: 767px)` в конце `style.css`.

**Главная тонкость — зазоры.** В Figma высота текстового блока обрезана по
чернилам (кегль 32 → блок 22), а в браузере блок равен строке (кегль 32 → 38.4).
Поэтому макетный зазор между двумя текстами нельзя переносить в CSS как есть: из
него надо вычесть выносы обоих блоков, иначе каждая пара разъедется на 10–20px.
Все зазоры в мобильном блоке — макетное значение минус выносы, посчитанные по
метрикам DM Sans (ascent .992em, descent .282em, высота прописной .7em).

**Короткие подписи.** Часть подписей в макете на мобильном короче. Обе лежат в
разметке рядом, видимую выбирают `.only-desktop` / `.only-mobile`, тексты —
ключи `*_short` в `content.json`. Это кнопки шапки («Contact me» → «Contact»,
«Download CV» → «CV»), разбивка заголовка в hero (на мобильном три строки вместо
двух) и заголовки первых двух карточек проектов («Kroshka kartoshka app» →
«Kroshka kartoshka», «EJS developer website» → «EJS developer»).

**Остальное:**

- карточки декора в hero на мобильном раскладываются по краям экрана — для этого
  они завёрнуты в `.hero__deco-row`, который на десктопе «растворяется» через
  `display: contents`;
- в Explorations показываются три карточки из шести
  (`.explore:nth-child(n + 4) { display: none }`), остальные остаются в разметке
  и включаются от 768px;
- макет мобильной версии содержит не все блоки — только примеры того, как они
  складываются, поэтому карточек проектов и работ в нём меньше, чем на сайте.
